# Plan v1 — todo-app

## Problem Statement

The scaffolded todo-app shows a greeting from its API. It has no todo list. A Developer cannot record a task or remove one, and the page looks like a default demo, not a government service. This Plan adds the two actions and a US Web Design System look.

## Solution

Add a small todo list to the existing SvelteKit page and a JSON API on the existing Hono server. The API keeps the list in memory while the process runs. The page loads the list, adds items, and removes them. The styling copies the US Web Design System: a system font, a plain top banner, strong blue buttons, and visible focus states. No new dependency is added.

## User Stories

1. As a **Developer**, I want to type a task and add it to the list, so that I can capture work without editing code.
2. As a **Developer**, I want to remove a task I no longer need, so that the list stays accurate.
3. As a **Developer**, I want clear feedback when a save fails, so that I know the list did not change.
4. As a **Developer**, I want the page to look like a United States government website, so that the app feels familiar and accessible.

## Implementation Decisions

### Modules

**Refactored**

- None.

**New**

- `server/src/todos.ts` — holds the list in memory and exposes `listTodos()`, `addTodo(text)`, and `removeTodo(id)`. It exports a Hono router mounted at `/api/todos`.
- `web/src/lib/todos.ts` — typed client functions `listTodos()`, `createTodo(text)`, and `deleteTodo(id)` that call the API.
- `web/src/lib/TodoForm.svelte` — text input and Add button.
- `web/src/lib/TodoItem.svelte` — one row with its text and a Remove button.

**Extended**

- `server/src/app.ts` — mounts the todo router and keeps `/health` and `/api/hello`.
- `web/src/routes/+page.svelte` — loads the list, adds and removes items, and shows loading, empty and error states.
- `web/src/app.css` — adds USWDS color and font tokens used by the page.

**Unchanged**

- `server/src/index.ts`, `scripts/smoke.ts`, the `deploy/` manifests, and the layout files.

### API contracts

`GET /api/todos`

- Returns `200` with `{ "todos": [{ "id": "string", "text": "string", "createdAt": "number" }] }`.
- Returns an empty list first.

`POST /api/todos`

- Takes `{ "text": "string" }`.
- Trims the text. It rejects empty text and text longer than 200 characters with `400` and `{ "error": "string" }`.
- Returns `201` with `{ "todo": { "id", "text", "createdAt" } }`. The id is a UUID. `createdAt` is Unix time in milliseconds.

`DELETE /api/todos/:id`

- Returns `204` with no body when the item existed.
- Returns `404` with `{ "error": "string" }` when the id is unknown.

### Data

No database and no schema change. The server keeps todos in one array in memory. The array is lost when the process restarts or when the Pod is replaced. The app runs one replica, so one process owns the list.

## Testing Decisions

- `server/src/app.test.ts` covers the API through `app.request`: empty list, add, reject blank and long text, delete, and delete an unknown id.
- `bun run typecheck` and the production build cover the Svelte page and the client module.
- `bun run smoke` still checks `/health` and `/api/hello`.
- Not automated: the visual look and the browser flow. The Project has no browser, and `smoke` is the end-to-end check.

## Out of Scope

- Marking an item complete or editing its text.
- Due dates, priorities, sorting and filters.
- Users, accounts and authentication.
- A database, migrations or data that survives a restart.
- Pagination for long lists.
- Undo after a remove.
- Hosting the real USWDS package or its build pipeline.

## Further Notes

- **Chosen over the alternative:** local browser storage needs no API, but the scaffold already ships a Hono API with `/api/*` CORS, and a server list keeps one shared state for every visitor. A database needs a resource that the namespace does not have.
- **Trade-off accepted:** the list is empty again after a restart. This fits a simple demo, and the Plan records it so later sessions do not treat it as a bug.
- **Scaling risk:** with more than one replica each Pod would hold its own list. Keep one replica, or add shared storage before scaling out.
- **Styling choice:** the look is hand-built with Tailwind classes. The real USWDS package would add a heavy asset pipeline for one page.
