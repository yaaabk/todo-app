# Plan v2 — todo-app

## Problem Statement

The todo page shows one boxer photo and plain text buttons. The Developer loves boxer dogs and wants the theme to fill the page. One photo and plain buttons do not carry the theme. The page feels like a task list that borrowed one dog picture, not a boxer app.

## Solution

Make the boxer theme fill the todo page. The server returns up to 3 boxer photos for one request. The page shows a hero photo, a pack strip and a boxer background. The hero photo is the large photo at the top of the page. The pack strip is the row of smaller boxer photos under it. The background is a boxer-coloured layer with a repeating paw pattern and two faded boxer photos.

The buttons carry boxer icons. The hero photo and the background move gently. The motion stops when the system asks for less motion. A fresh photo still arrives when the Developer adds a task.

This adds to the todo page from the previous Plan. It does not replace the task list, the todo API or the due date labels.

## User Stories

1. As a **Developer**, I want to see several boxer dogs at once, so that the page feels full of them.
2. As a **Developer**, I want a boxer background, so that the app feels themed before I read the list.
3. As a **Developer**, I want boxer icons on the buttons, so that the actions look like part of the theme.
4. As a **Developer**, I want the boxer photos to move gently, so that the page feels alive without distracting me.
5. As a **Developer**, I want the motion to stop when my system asks for less motion, so that the page stays comfortable.
6. As a **Developer**, I want the fresh boxer photo to arrive when I add a task, so that the page stays fun to use.

## Implementation Decisions

### Modules

**Refactored**

- `web/src/routes/+page.svelte` gains the boxer background, the pack strip and the boxer icons on the buttons. It keeps the form, the list and the due date labels.
- `server/src/app.ts` changes `GET /api/boxer` to return a list of photos.
- `server/src/app.test.ts` and `web/src/routes/page.test.ts` grow cases for the new photo payload, the background, the pack strip and the icons.

**New**

- `web/src/lib/boxer.ts` calls `/api/boxer` and normalises the reply to `{ url, images }`. The page imports it as `#lib/boxer`.
- `web/src/lib/boxer.test.ts` tests the normaliser.
- `web/src/lib/BoxerIcon.svelte` draws a boxer or paw icon as inline SVG. It takes a name and a CSS class.
- `web/static/paw-print.svg` is the paw shape the background repeats.

**Extended**

- `web/src/app.css` holds the boxer colours, the background layers and the keyframes.

**Unchanged**

- `web/src/lib/todos.ts`, `web/src/lib/format.ts`, `server/src/todos.ts`, the deploy manifests and `scripts/smoke.ts`.

### API contracts

- `GET /api/boxer` returns `200` with `{ "url": "...", "images": ["..."] }`. `images` holds 1 to 3 URLs. `url` equals the first entry.
- The route asks `dog.ceo` for 3 random boxer photos. It uses a 2 second timeout.
- The route drops any entry that is not a non-empty string. If no entry remains, it returns `{ "url": "/boxer-fallback.jpg", "images": ["/boxer-fallback.jpg"] }`.
- The route never returns an error. A slow or failed `dog.ceo` call falls back to the bundled photo.
- The todo routes stay the same. The page still calls `GET /api/todos`, `POST /api/todos`, `PATCH /api/todos/:id` and `DELETE /api/todos/:id`.

### Data

None. The plan adds no schema, no database and no new storage. It changes only the shape of the `GET /api/boxer` reply. The todo store stays in memory.

## Testing Decisions

The server tests stub the outgoing `dog.ceo` call. They cover a reply with 3 photos, a reply with one invalid entry and the fallback when the call fails. They must not reach the real internet.

The `boxer.test.ts` unit test covers a reply without an `images` field. It also covers an empty image list.

The component tests render `+page.svelte` with `fetch` stubbed through `vi.stubGlobal`. They cover the pack strip with extra photos, the background layer and its photos, and the icons in the buttons. The existing tests stay.

`bun run smoke` keeps its current checks. The new routes need no new runtime wiring.

The plan does not automate CSS colour or animation timing, because jsdom does not paint.

## Out of Scope

- Any change to the todo routes, the todo store or the due date labels.
- A new dog photo file in the repository, beyond the fallback that already exists.
- An icon library or a new dependency.
- Audio.
- Any change to the Kubernetes manifests.
- User accounts, login and persistent storage.

## Further Notes

- **Chosen:** extend `GET /api/boxer` instead of adding a new route. One route keeps one fetch path and one fallback.
- **Chosen:** draw the icons as inline SVG in a Svelte component. The app needs no icon package.
- **Chosen:** build the background from CSS and photos in the same reply. The page makes no extra request.
- **Chosen:** make the background photos and icons decorative. They use empty `alt` text and `aria-hidden`, and the button labels stay text.
- **Risk:** `dog.ceo` may return fewer than 3 photos. The page shows any number from 1 to 3.
- **Risk:** `dog.ceo` may be unreachable from the cluster. The bundled fallback photo covers that case.
- **Risk:** animation can distract or cause motion sickness. The CSS disables the motion under `prefers-reduced-motion`.
